# Configuration and API reference

## Configuration ownership

| File | Purpose | Owner |
| --- | --- | --- |
| `infra/terraform.tfvars` | Account, public URLs, storage, CORS and webhook receivers. | Installation operator; consumed by OpenTofu. |
| `wrangler.jsonc`, `auth/wrangler.jsonc` | Application entry points, build settings, binding names, migrations and local defaults. | Application; consumed by Wrangler and OpenTofu. Keep these files valid JSON. |
| `wrangler.deploy.json`, `auth/wrangler.deploy.json` | Base configuration combined with installation settings and provisioned resource IDs. | Generated by OpenTofu; do not edit. |
| `.env` | `CLOUDFLARE_API_TOKEN` for OpenTofu and Wrangler. | Operator's local deployment environment. |
| `.dev.vars` | `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` for media signing. | TAMS Worker secrets, uploaded by Wrangler. |
| `auth/.dev.vars` | `BETTER_AUTH_SECRET`, at least 32 random characters, for signing-key encryption. | OAuth Worker secret, uploaded by Wrangler. |
| `auth/.env.operator` | `AUTH_OWNER_PASSWORD`, at least 32 random characters. | Local operator CLI; never deployed. |

Secret files, installation inputs, generated configuration and OpenTofu state are ignored by Git. Secret files must use mode 0600. OpenTofu receives no runtime secrets. Preserve its state and keep `BETTER_AUTH_SECRET` with D1 backups.

OpenTofu owns R2 buckets and their CORS policies, D1 creation and generated configuration. Wrangler owns Worker deployment, secrets, bindings, D1 schema migrations, Durable Object migrations and `workers.dev` setup. See [Install](deployment.md#install) for the command order.

## Installation inputs

The input schema is in [infra/main.tf](../infra/main.tf), [infra/auth.tf](../infra/auth.tf) and [infra/cors.tf](../infra/cors.tf). [terraform.tfvars.example](../infra/terraform.tfvars.example) shows a complete configuration.

| Input | Default or requirement |
| --- | --- |
| `account_id` | Required, 32 lowercase hexadecimal characters. |
| `auth_issuer` | Required, public HTTPS origin of the OAuth Worker, with no path, port or trailing slash. |
| `tams_audience` | Required, public HTTPS origin of the TAMS Worker, with no path, port or trailing slash. |
| `storage_backends` | One `MEDIA` backend using bucket `cf-tams-media` and label `cloudflare:r2`. |
| `webhook_allowed_hosts` | `[]`; all webhook registrations rejected. |
| `api_cors` | `{}`; no allowed browser origins. |
| `media_origins` | `[]`; no R2 browser CORS policy. |
| `media_cors` | Defaults below; active only when `media_origins` is non-empty. |

### Storage backends

`storage_backends` is a map keyed by Worker binding, such as `MEDIA`. Each entry requires `bucket_name`, a UUID `storage_id` and a non-empty `label`. Optional `tags` maps strings to lists of strings and defaults to `{}`. `default_storage` defaults to false; exactly one entry must set it to true. IDs, bucket names and labels must be unique within the installation.

All controlled backends are private R2 Standard buckets in the same account, using one media CORS policy and one signing credential scoped to those buckets. The generated `STORAGE_BACKENDS` registry and R2 bindings come from the same input. Discover runtime IDs through `/service/storage-backends`.

Backend IDs, bucket names and endpoints are permanent identities once persisted; the store rejects removal or remapping. Labels, tags and the default may change. `STORE_ID` selects the installation's Durable Object and defaults to `default`. Preserve it, the `TamsStore` class and its migration history across updates.

### CORS defaults

Origins contain a scheme, hostname and optional port, without paths or trailing slashes. HTTP and HTTPS are accepted. `*` permits any origin; `*.example.com` patterns are not supported for CORS. Credentialed API CORS requires explicit origins. An explicit bearer Authorization header works with the default `allow_credentials = false`.

| Setting | `api_cors` | `media_cors` |
| --- | --- | --- |
| `origins` | `[]` | Supplied by the separate `media_origins` input. |
| `methods` | `GET`, `HEAD`, `POST`, `PUT`, `DELETE`, `OPTIONS` | `GET`, `HEAD`, `PUT` |
| `headers` | `Authorization`, `Content-Type` | `Content-Type`, `If-None-Match`, `Range` |
| `expose_headers` | `Location`, `Link`, `WWW-Authenticate`, `X-Paging-Limit`, `X-Paging-Count`, `X-Paging-Reverse-Order`, `X-Paging-NextKey`, `X-Paging-Timerange` | `ETag`, `Content-Length`, `Content-Range`, `Accept-Ranges` |
| `max_age_seconds` | `3600`; non-negative integer. | `3600`; integer from 0 to 86400. |
| `allow_credentials` | `false` | Not an input. |

API preflight requests with an allowed origin, method and headers return 200 without a bearer token. A rejected preflight returns 400. With no configured origins, API CORS handling is disabled. Actual API requests still require authentication.

R2 handles OPTIONS preflights through its bucket policy. Set `media_cors.methods` to the actual request methods, such as GET or PUT; OPTIONS is not a valid input there.

The OAuth Worker's `CORS_ORIGINS` is generated from `api_cors.origins`. Its own policy permits POST to the token endpoint and GET to discovery and JWKS, with Authorization and Content-Type headers. Allowed preflights return 204; rejected origins or preflights return 403. Responses expose `WWW-Authenticate` and `Retry-After`; the preflight cache lifetime is 3,600 seconds. Token responses use `Cache-Control: no-store`.

For local development, the API's `API_CORS` defaults to `{}` and the issuer permits `http://localhost:3000`. The [browser access guide](deployment.md#configure-browser-access) shows local overrides and deployment steps.

### Webhook receivers

`webhook_allowed_hosts` accepts exact hostnames and leading `*.` subdomain patterns. `*.example.com` matches any subdomain, including `hooks.eu.example.com`, but excludes `example.com`. Matching ignores case and a trailing dot. Entries must omit scheme, port and path. A bare `*`, other wildcard forms and wildcards over IP addresses are unsupported.

The same allowlist applies to registration, updates and delivery. Receiver URLs must use HTTPS; private addresses, custom ports and redirects are rejected even for listed hosts. Rejections log only the target hostname. See [Enable webhooks](deployment.md#enable-webhooks).

## Endpoints

Paths below are relative to the indicated Worker origin. Local origins are `http://127.0.0.1:8787` for TAMS and `http://127.0.0.1:8788` for OAuth.

| Worker | Method and path | Access and purpose |
| --- | --- | --- |
| TAMS | `GET /healthz` | Public liveness check. |
| TAMS | `GET /readyz` | OAuth; checks metadata access. |
| TAMS | `GET /openapi.json` | OAuth; served TAMS API contract. |
| TAMS | `GET /service` | OAuth; service discovery. |
| TAMS | `GET /service/storage-backends` | OAuth; configured storage backends. |
| OAuth | `POST /api/auth/oauth2/token` | Client credentials, form encoded; `grant_type=client_credentials`. |
| OAuth | `GET /.well-known/oauth-authorization-server` | Public OAuth discovery. |
| OAuth | `GET /api/auth/jwks` | Public signing keys. |

The full API is specified in [BBC TAMS 8.2](https://github.com/bbc/tams/blob/8.2/api/TimeAddressableMediaStore.yaml). There is no public operator login, client registration or administration endpoint. Use the [operator CLI](oauth.md#provision-clients).

## OAuth permissions

| Scope | Access |
| --- | --- |
| `tams-api/read` | Browse metadata, Profiles and webhooks; obtain playback URLs. |
| `tams-api/write` | Create and update Flows, Profiles, metadata and webhooks; allocate uploads, register Segments, and copy or delete Object instances. |
| `tams-api/delete` | Delete Flows or Segments and inspect individual deletion requests. |
| `tams-api/admin` | All operations, including service configuration, changing `read_only` and listing all deletion requests. |

Write and delete do not imply read. All these scopes permit service discovery. Empty or unrelated scopes grant no API access. Insufficient permissions return 403 with an `insufficient_scope` bearer challenge.

The policy follows the [BBC TAMS 8.2 coarse-grained authorisation model](https://github.com/bbc/tams/blob/8.2/docs/appnotes/0016-authorisation-in-tams-workflows.md). Webhook PUT and DELETE require write permission, a deliberate restriction relative to the application note's suggested read permission. Profiles follow the ordinary read/write split. Changing `read_only` through a full Flow PUT also requires administrator permission.

Clients use their registered method: `client_secret_basic` by default, or `client_secret_post` when provisioned with `--method`. Omitted `scope` uses the client's authorised defaults; omitted `resource` targets this installation's TAMS API. Refresh tokens and interactive login grants are not provided.

Signing keys rotate after 30 days; previous public keys remain available for another day. The verifier caches keys for five minutes, with a 30-second cooldown between unknown-key refreshes. Invalid tokens return 401; unavailable verification returns 503. Cached keys permit verification during a temporary D1 outage until a refresh is needed.

## Scope and limits

cf-tams implements the TAMS 8.2 API for one installation with multiple controlled R2 buckets. Profiles, collections, init Objects, external Object instances, tag filters and bulk Segment registration use the shared TAMOSS domain rules. Qualification procedures and their limits are described in [Qualify the API](deployment.md#qualify-the-api).

| Operation | Application limit or lifetime |
| --- | --- |
| OAuth access token | 15 minutes, with 30 seconds of clock tolerance. |
| Token request body | 16 KiB, with a ten-second read deadline. |
| Token rate | 60 requests per minute per client IP at each Cloudflare location; shared-address clients share the allowance. This is not a global quota. |
| TAMS request body | 4 MiB, with a 30-second read deadline. |
| Allocation or Segment registration batch | At most 1,000 Objects or Segments. |
| Signed media URL | One hour, independent of OAuth token expiry. |
| Physical Object retention | At least 24 hours from allocation; cleanup runs asynchronously. |
| Object copy | Controlled R2 source, at most 5 GiB; two copies per alarm batch, 30 seconds per attempt, retry after 30 seconds. |
| Webhook delivery | Ten per alarm batch, ten seconds per attempt, backoff up to five attempts; duplicate delivery is possible. |
| Completed job records | Retained for one day. |

Requests and alarm batches run serially within the metadata store. Webhook and copy I/O can delay API requests. Cloudflare's [Durable Object limits](https://developers.cloudflare.com/durable-objects/platform/limits/) also apply, including 10 GB of SQLite storage per Durable Object. Media bytes live in R2.

External-source copying, multipart copies, replication policies, CDN caching, Access/OIDC, a media browser, managed ingest, transcoding and existing-store migration tooling are outside this implementation. Local R2 emulation has no S3 presigning endpoint; signed transfers require deployed R2.
